# 整体架构与流程

## 当前主流程

**下载 → 平台/内封字幕 → 本机 whisper（可关闭） → 原语言字幕 → 中文全集索引 → 统一方案 → 全文写稿 → 事实与全文连贯性评审 → 人工审稿 → 本机配音 → 16:9横屏成片**。

一集一篇连续稿、一条成片；时长预算为原片30%，按约4字符/秒估字数，剧情完整与字幕证据优先，不凑时、不定格、不慢放。DeepSeek 文本 API 会收到字幕与稿件，画面/音轨不作为 AI 输入。API 配置见 README。

## 模块

| 位置 | 职责 |
| --- | --- |
| `commands/pipeline.rs` | 素材准备、原语言字幕质量、旧翻译失败恢复、任务列表与删除 |
| `commands/episode.rs` | load/generate/save/review/render_episode，任务锁、源版本与全文版本检查 |
| `services/episode.rs` | 全集索引、方案覆盖、全文或续写、双层评审、最多两轮局部修复、横屏字幕与出片 |
| `prompts/episode/*.md` | index/story/write/review/repair 纯模型指令，编译内嵌 |
| `services/script.rs` | 字幕锚定时间窗、证据引文与原速储备校验、实测配音镜头分配、字幕切分 |
| `services/ai.rs / llm.rs` | 后端 DeepSeek 配置、JSON请求、字段级schema诊断与一次有限格式重试、结构化反序列化 |

| `services/tts.rs / technical_review.rs` | 本机 say 内容缓存、估算字词时间、最终静音/黑场/静止检查 |

## 全集梳理与生成

不再调用全文翻译：保留原语言TRANSCRIPT及时间戳。外语字幕直接输入DeepSeek，事件/方案/中文稿用中文，evidence_quote保留逐字原文；评审跨语言核对含义，不把中文译句当原文引文。旧translate模块已从生产移除。旧翻译失败任务重试时，在start_stage清空错误前识别失败原因，若规范原文存在、来源受支持且质量合格则直接复用，只经应用状态机标ready，不重下或重跑ASR；不合格则走正常获取。已经成功安装的历史译文不自动覆盖回原文。

1. 字幕按时间形成稳定全片Shot ID。排除策略marker-local-v2取消无标记时固定删除前60秒/后90秒：音乐符号、重复对白、完结提示仅作候选；明确歌曲/演职员署名或广告标记按设置只排除该条实际区间，不跨间隙扩展，不由单条标记吞掉整段片头片尾。生成保存exclusion-report.json，绑定源/字幕版本、设置、原始区间、候选理由/检测方法/是否应用、保留与排除字幕位置。界面可刷新查看；暂无逐区间确认编辑，用户通过关闭对应跳过设置保留所有候选。时间窗不是视觉分镜，不猜眼神表演。整集采用 `episode_shots` 保留短回复与单字字幕，不沿用旧短片<4秒丢弃规则；仍过滤无效时间、空文字与排除区间，片头广告误判需人工核对。
2. 每块最多48个字幕窗、约6000字符，提取事件、人物与未决问题，给边界上下文及明确required_shot_ids。先保存原始索引，再校验引用；块外/非法证据立即拒绝。缺失ID按每批≤16窗最多两轮补充，只增补不改已有事件，补后仍缺失则显示数量/ID并停止；记录initial/coverage/supplement/merged诊断。完整有效块按原片/字幕版本、实际输入、模型地址/ID、提示版本指纹缓存在runs/index-cache，重试重新校验后复用，不含密钥，不缓存失败块。
3. 汇总为一个事件列表与统一方案，要求每个事件明确 keep/omit 与理由；保留事件须被节点引用。程序只验证引用和覆盖声明，是否遗漏重要事实仍依赖评审与人工。
4. 全文目标≤5000字符且材料在安全输入预算内时优先一次写稿。否则按统一方案连续续写，携带完整已写正文、人物与揭示方案、已用ID；不独立分章节。全文节点引用覆盖检查，旧稿 checkpoint 保留诊断。
5. 单次输入保守限制为100000 Unicode字符，输出阶段上限24000 tokens，索引8192。不是声称模型的真实token上下文容量；服务若不支持预算会显式报错。超预算停止不截材料，不自动多级摘要或自动从检查点续跑。

## 评审、版本与保存

DeepSeek JSON模式不强制schema。完整JSON若结构不符，后端给出schema自有字段路径及规则（最多4项），不回显实际值/未知字段名/正文；同一业务调用最多一次格式重试，仍须严格满足原schema。不把字符串ID强转、不丢额外字段或伪造缺失评审。HTTP、截断、工具调用、空正文或非法JSON不触发盲重试。错误标注全文评审/AI局部修稿/联网规划阶段。格式重试有额外API用量，但不新增业务修稿轮数，业务两轮上限不变。

- 每轮同一请求检查所有段落事实和全文连贯性，携带完整正文、方案、事件索引与关联原字幕证据。超过应用预算就明确标未通过，不只看摘要冒充全文。
- 事实每段恰好一结论；pass须有证据，insufficient_evidence进入修稿（补查相邻字幕、纠正/收窄/删去无证据从句），不再立即终止。全文问题定位一个或多个段号，支持接点两侧联动修复。
- 合并程序/事实/连贯性问题，只替换允许段，base_revision匹配；标题/段数/其他段冻结。最多两轮、三次评审，无变化、越权或无效评审停止；问题增多不会提前终止，但没有额外轮数。保留程序合格且问题较少候选，未通过不得出片。
- 复审携带上轮意见、对应版本与实际修改段号；旧意见不作事实，不重复已删断言，不因简称/同义表达或措辞偏好反向修稿。事实新增矛盾仍须指出。失败回退候选与其原评审成对保存为retained-candidate-review.json，界面错误只列保留版本的问题；同问题数时保留较新候选，避免稿件与最后一轮错误错位。
- 候选始终与通过区分：失败在 review_error 显示，reviewed_revision 为空。失败候选可以人工编辑保存，但不可出片。只在当前全文程序与双层检查均通过时绑定 reviewed_revision。
- 保存不强制草稿已通过规则，以便保存修复中稿；正文改变立即使评审与当前输出引用失效，之后需重新评审。旧文件仍保留，不默默删除。
- 原片/字幕改变，或当前排除策略/设置形成的字幕窗与稿件记录不一致时，旧整集只能查看、不能保存/评审/出片，必须重新生成，不自动覆盖旧稿。重新生成有 expected_revision，成功后归档旧整集并替换当前；失败保留旧稿。

## 可选联网查证与自动终稿

TAVILY_API_KEY从同一后端.env读取；缺失时不搜索但审稿/修稿继续。生成和单独重评都复用同一research会话，首次需要修稿时由DeepSeek规划一次最多3条短查询，限160字符、定位到问题段，过滤长原句摘录，不把完整字幕或稿件发Tavily。固定https://api.tavily.com/search、Bearer鉴权、basic深度、最多3条摘要/查询，25秒超时、256KiB响应上限，不跟重定向、不抓取页面或执行网页。

结果记录在web-research.json与Episode.research（serde默认兼容旧稿），包括查询、用途/问题段、来源URL/标题/片段、搜索错误；不含Key或服务错误正文。UI只显示用途和来源。结果以web_reference_untrusted提供修稿与复审，忽略网页指令，不能替代字幕证据/画面储备；搜索失败不算查证通过。用于词义/译名/背景定位，不用小说/跨集信息补剧情。

通过程序与双层复审的同版本写accepted.json，状态为AI通过待人工确认；未解决的真实转写缺损或结构问题仍会阻断。自动修稿可以删除不可靠从句、收窄结论，但不擅自增删段或改主线。人工审稿和最终看片不被AI自动批准取代。

## 原速16:9出片

出片必须当前全文评审版本一致、程序校验通过、IPC收到人工确认。say新合成与缓存音轨先独立解码并检查能量/静音（-50dB、0.2秒检测，边缘≥2秒/内部≥3秒静音阻断；近乎全静音亦阻断），缓存旁保存audio-review.json。渲染再在混音前保存narration-review-NNNN.json；BGM或原声无法替缺失旁白过关。这不验证朗读语义、错漏字或全文读出，报告semantic_coverage_verified=false，纯音同样可能能量通过，不虚称语音识别。say逐段完整合成，按实测时长从同情节字幕窗原速截取；画面不够或任一截取<1秒失败，不裁配音、不改速。配音响度归一、原声侧链避让，可混本地BGM。

合并为一条连续音画，裁掉设置中的原片底部字幕条（可为0），等比缩放补边到1920×1080，不拉伸、不再用模糊竖屏背景或全程顶部标题。解说字幕白字居底，按实测音频时长估算，不是词级强制对齐。

异常区间按日志事件顺序配对，孤立end不错配后续start；freeze/silence/black在EOF未闭合的start按实际媒体时长闭合，纳入报告。最终视频与配音累计时长差>0.5秒阻断；在加BGM和烧字幕后的实际最终视频检查静音、黑场、静止。静音阻断，黑场/静止提示；最终技术检查不证明内容、画面匹配、字幕位置或混音听感都正确，仍须人完整看片与只听声音。

## 短证据与下一批边界

script::validate_evidence独立检查原文/引用，短于0.8秒的否定回复不失去证据资格；短引文仅在等于完整引用窗原文时允许。现有validate/timing仍按共用shot_ids校验画面（窗口≥0.8秒、最终裁剪≥1秒及≥4有效字符引文），不为通过放宽剪辑时长。半秒否定句可入索引并通过独立文字检查，但选为画面仍阻断；真正独立evidence_refs与candidate_visual_ids要下一批显式schema迁移，当前未假装完成。

无额外模型，本批仅规则/现有FFmpeg检查；视觉/WhisperX/说话人/新增文本模型须先请示用户再引入。

## 任务目录与兼容

```text
episode/
  episode.json                    # 当前方案、全文、证据、版本、评审和输出
  runs/generate-*/                 # index-*.json / story.json / draft-checkpoint.json / review/
  runs/review-*/                   # before.json / candidate / audit / repair / result
  tts/                            # 按文案音色缓存
  renders/run-*/                  # episode.mp4 / .srt / .ass / technical-review.json
```

`shorts/` 及旧命令保留供兼容，不被新生成覆盖。队列暂复用 shorts_total/shorts_rendered IPC字段存一条episode计数，主界面不再显示旧短片入口。生成/渲染失败留下诊断目录但不写成功 output_path。正文检查点尚无自动恢复协议，重试生成会新建run；已校验索引块可跨run缓存复用，音频缓存可复用，部分视频不自动复用。

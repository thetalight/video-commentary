# 字幕驱动的整集长视频解说 Skill 设计

## 1. 已确认目标与当前交付

**一集生成一篇连续长稿、一条整集解说成片，不拆成多个一分钟短片，不按独立章节各写一稿再拼接。**

目标流程：

```text
已完成的原语言规范字幕（不先全文翻译）
  → 全集材料分块梳理（读取边界，不是章节）
  → 合并全集事件、人物与证据索引
  → 一份统一故事线与叙事方案
  → 全文写稿（有效预算足够时优先一次生成）
     └─ 仅超预算时按同一方案连续续写
  → 逐段事实评审 + 全文连贯性检查
  → 最多两轮有范围的局部修复
  → 人工通读审稿
  → 本机配音、原速剪辑、整集成片及人工验收
```

**用户已确认：原片约30%时长预算 + 16:9横屏。** 剧情完整和字幕证据优先，不强制凑时。

主界面已接入episode链路：全集索引、统一方案、全文或连续续写、双层评审、有界修复、独立保存与横屏成片；旧shorts保留兼容。纯提示在src-tauri/prompts/episode/，运行契约见[ARCHITECTURE_AND_WORKFLOW.md](ARCHITECTURE_AND_WORKFLOW.md)。目前只做mock与构建验证，未读真实字幕或调用真实API/媒体制作。超安全输入停止、自动续跑尚未实现。

## 2. 为什么不按章节独立写

各章独立写再拼接容易出现重复人物介绍、段段钩子、称呼漂移、情绪反复重启、提前剧透和铺垫丢失。之后加一句过渡或自由重写全文，都不是可靠修法。

本设计区分三类边界：

| 边界 | 用途 | 不意味着什么 |
| --- | --- | --- |
| 字幕读取块 | 在上下文预算内读完整集并建立证据索引 | 每块都要产生一个独立故事 |
| 文案生成块 | 仅在全文无法稳定一次输出时连续续写 | 章节标题、独立开场或独立结尾 |
| 配音/事实检查段 | 完整口语意群的缓存、验证与时钟 | 每段都是独立短片 |

全文足够短且证据能放进有效上下文时，一次写初稿更利于整体组织；但一次生成也可能不连贯，必须评审。超出预算时不能截去后半集、忽略证据或把独立章节拼接伪装成续写。

## 3. Skill 结构

```text
.agents/skills/
  commentary-episode/
    SKILL.md
    references/contracts.md   # 目标边界 + 明确标记的旧 shorts 代码契约
  commentary-story/SKILL.md   # 全集索引与唯一叙事方案
  commentary-script/SKILL.md  # 全文生成与必要时连续续写
  commentary-review/SKILL.md  # 事实 + 全文连贯性 + 有界修复
  commentary-delivery/SKILL.md # 一条长片的配音、合成、验收
```

旧 `commentary-shorts / commentary-scout` 已更名为 `commentary-episode / commentary-story`，不保留会误触发短片方案的并列 skill。其他三个名称不变，内容改为整集目标。

刷新技能资源后可使用：

```text
/skill:commentary-episode 设计整集解说的实现迁移，先确认未定参数
/skill:commentary-story 用虚构字幕检验跨块因果与人物关系索引
/skill:commentary-script 设计统一全文写稿及超预算续写，不独立分章节
/skill:commentary-review 用合成稿测试称呼漂移、提前揭示与接点修复
/skill:commentary-delivery 分析长片累计时钟与恢复设计，仅检查源码
```

Skill 是项目助手的工作规范，不是桌面端自动加载的模型插件。相对链接从 skill 所在目录解析，不从 shell 当前目录解析。

## 4. 全集方案与连续续写的最小状态

### 全集索引与方案

先读完全部有效字幕，追踪块覆盖与失败状态；广告等按规则排除，不能每块只保留几个高分场面。合并跨块事件、人物别名和关系变化，保留源 ID、时间与证据导航。记录主要剧情、必要支线、因果、人物知情、铺垫和本集未决事项。

统一方案明确叙事视角、主线、必要前提、信息揭示次序、节点衔接、开头承诺及结尾。内部节点用于规划，不是独立创作章节；多线剧情可以切换视角，不能为只跟随一人而删掉理解结局所需的事件。

索引与方案不是事实替代物，人物、数字、因果和结果仍需回查字幕。字幕时间窗也不证明画面中存在某种动作或表情。

### 预算与续写

预算包括阶段指令、证据、方案、历史状态、输出 JSON 开销与余量。`llm.rs` 当前实际传入的上下文和输出上限必须纳入检查，不能仅凭模型宣传窗口判断。

优先一次全文生成；仅超预算时启用续写。每次续写接收：

- 同一全集方案与当前节点；
- 人物称呼表、关系和知情变化；
- 已完成节点与已写事实记录、必要前文原句；
- 上段结尾、本段进入点与下一接续点；
- 已揭示/未揭示信息与未回收铺垫；
- 当前原字幕证据、稳定源 ID、已用画面清单；
- 剩余预算与源材料/方案/前文版本。

状态从已保存并校验的正文更新，不只信任模型自报覆盖。前文修订使相关续写状态失效，不能继续沿用过期摘要。所有块合为一个全文 revision 后统一评审，不把每块通过拼成全文通过。

## 5. 双层评审与受控修复

| 检查 | 输入与关注点 | 通过条件 |
| --- | --- | --- |
| 程序校验 | ID、时间、引文、画面累计储备、版本与完整性 | 确定性规则均成立 |
| 逐段事实 | 当前稿段落与原字幕；人物、数字、归属、因果、结果 | 全文每段有明确结论与依据，缺段/不可用不通过 |
| 全文连贯性 | 完整稿、全集方案、人物与揭示索引 | 覆盖主要剧情，称呼一致、因果清楚、不重复、揭示有序、铺垫与结尾成立 |
| 人工审稿 | 同一当前全文及全部警告 | 人实际通读确认，不能由机器代签 |
| 最终验收 | 本轮最终文件 | 人完整看片和只听声音复核，技术检查不能替代 |

全文评审超上下文时，需全局索引检查、正文连续覆盖扫描（带重叠）、远距离铺垫/回收原文对照和全局复核。仅看摘要或每段不能称全文通过。预算不足以完成时明确“未完整检查”。

问题定位到全文段号和证据/相关段，合并为明确修复范围。接点可联动修改两侧；远距离称呼问题可包含确实受影响的多段，不等于任意全文可改。修复绑定 `base_revision`，冻结其余正文、段数、标题和方案，之后重新核程序、事实、接点与全文状态。

insufficient_evidence现在进入问题段自动修复，而非立即终止；先看原文上下文、纠正或收窄/删除无据断言。问题段增多也可使用剩余轮数，仍最多两轮；保存程序合格问题较少候选，未解决则待人工。可选Tavily在首次修稿时规划最多3次关键词查证，资料以不可信外部参考提供，不能替代本集事实或伪造引文。缺Key/失败仍仅据字幕修改。

最多两轮局部修复，不能按块重置轮数。主线错误或需要增删段时停止局部循环，回到方案并请求确认，不用一次自由“全文润色”改坏已核实内容。

## 6. 实现落点与剩余限制

准确的新旧字段与门禁见 [contracts.md](../.agents/skills/commentary-episode/references/contracts.md)。以下为原迁移分工，基础路径现已接入；不是声明已具备无限长稿件处理或自动恢复：

1. **任务与数据**：已实现 Episode 容器、稳定全集ID、源材料/正文版本、事件索引、统一方案、reviewed_revision和生成检查点；新旧目录隔离。方案随生成固化，当前没有单独编辑方案接口；检查点不自动恢复。
2. **全集控制器**：已移除主入口的高光条数/局部窗口预算，索引每块必须覆盖全部有效字幕窗（短回复也保留）；方案所有事件需keep/omit决定，保留事件须节点引用。程序能验证覆盖声明，不证明语义理解完整。
3. **纯提示接入**：index/story/write/review/repair五个文件用include_str内嵌；写作只附所选风格节。事实与全文检查在同一个完整上下文请求内给两个结果集合，不是仅逐段评审。
4. **评审与保存**：已接入独立保存和重评，修改失效旧结论，候选失败显示review_error。修复仅授权段号、全局两轮上限；当前必须双层通过才允许出片，没有人工绕过未通过稿的开关。
5. **媒体与界面**：已接入EpisodePanel/EpisodeWorkspace、人工确认和1920×1080等比缩放补边，配音与原速时钟复用现有应用服务。最终混音/烧字幕后技术检查；音频缓存可复用，部分剪辑不自动续跑。
6. **验证范围**：已用虚构字幕和mock请求测试一遍写全文/必要续写、覆盖、版本失效、接点联动修复、两轮上限及16:9过滤器。构建测试不是内容效果或真实媒体验收，尚未实跑DeepSeek和应用整集出片。

当前实现用100000输入字符保守预算、长阶段24000输出tokens；≤5000目标字符且输入可容纳时一次生成，否则携完整已写正文连续续写。超预算显式停止，不做分层全文评审；生成检查点与音频缓存保留，但尚无自动从旧检查点续跑。原片/字幕变化会拒用旧稿；修改正文使旧评审和当前输出引用失效。最终技术检查针对混音/烧字幕后的横屏文件。程序硬规则、版本、并发和两轮上限仍由 Rust 执行，不迁为“模型承诺”。评审未全通过/未完整检查候选只能显式待人工核对，不虚构 accepted 或发布批准。

## 7. 隐私与参考取舍

AI 已按用户要求改为后端 `.env` 配置的 DeepSeek API（默认官方实测模型ID `deepseek-flash` 原样发送；原 DeepSeek-V4.1-Flash 字符串被官方返回400拒绝，不回退 Ollama），原语言字幕梳理、写稿和评审的文本会发送到该地址；不再全文译中，中文稿直接对照原文，证据引文保持原语言。Key 不传前端或任务、不回显，模型可用性需由实际服务支持。保留本机 whisper、say；字幕唯一事实源；不把画面喂给模型；原速、不定格、不慢放；每段所选画面至少为文字字符数 ×0.3 秒。成片以实测配音时钟为准，不静默截音或删稿。

授权配置的 DeepSeek 不等于授权任意助手或其他服务；未另行确认时，不把真实字幕/文案/画面/含内容评审读入当前会话；优先源码、合成例子与本地不含内容的计数、错误码、时长。不得直接运行媒体命令制作任务产物。

参考：[zenstory-ai/video-recap-skills](https://github.com/zenstory-ai/video-recap-skills/tree/main)。借鉴阶段职责、先故事后句子、创作与机械执行分开、局部修改冻结及完整观看验收。之前阅读的 main 归档 SHA-256 为 `aa1a5ad37e2039d826e99f12d3967cbb12fb058eab02e1469baf9fb6984bc21e`，不是固定 commit ID。

不引入其云端 ASR/VLM/TTS（DeepSeek 仅用于文本 AI）、把外部剧情当本片事实的调研、声音克隆、多源素材库、剪映导出或先剪完整母版再写稿。规范为本项目重新编写，未复制可执行脚本或依赖。

成本调整：已移除全文翻译生产路径及其10%未译阈值。旧翻译失败重试复用合格原字幕；英文the不再被派生文本清理删除。新增原文保留、英文引文/中文叙事与mock跨语言生成测试。后续索引/方案/评审仍有API用量，缓存和局部修复输入优化不在本次范围。

P1已接入schema-v2：evidence_refs与visual_selections独立，支持短证据/重复引用、人工必保时间区间，AI仅可新增所引完整字幕窗保护且不能移除已有保护。旧v1只读投影，显式迁移先归档旧稿再复制字段，清旧评审后重评；材料变化拒绝迁移。配音实测后先生成版本绑定edit-plan.json，保护包络再分配余量，冲突不渲染，不再窗口前部比例截取。UI分别编辑证据和画面，改保护亦失效评审。当前候选仍字幕关联窗，计划秒级、未VFR逐帧/视觉切点或句界吸附，原声主导段、多轨timeline后续处理；无新增模型。合成测试覆盖半秒否定、100–110内保护107–109且音频6秒、包络冲突、证据复用/画面不重叠、保护不可被AI删除及迁移失效。

## 8. 验收用例（部分已由mock单元测试覆盖，非真实API或成片验收）

| 用例 | 期望 |
| --- | --- |
| 字幕已完成 | 直接全集梳理，不重新下载/转写/翻译 |
| 跨块事件/同名歧义 | 合并有据，同一事件不重复，无法确认不猜 |
| 关键前提不“精彩” | 仍保留，不以高光评分删掉必要因果 |
| 全文与证据预算足够 | 一次生成完整候选，仍做双层检查 |
| 全文超预算 | 连续续写，携带统一状态，不独立分章节 |
| 续写第二块重复介绍或提前公布结局 | 全文评审定位接点与揭示问题，不作为完整通过 |
| 修改前文或方案后恢复 | 拒绝过期检查点，重建受影响状态 |
| 输出截断或遗漏后半集 | 标未完成，不发布残稿 |
| 仅每段或摘要通过 | 不冒充全文连贯性通过 |
| 引文存在但叙述虚构 | 事实评审阻断；程序引文匹配不能救场 |
| 接点指代或因果断裂 | 授权修相关前后段，其余冻结，重核全文 |
| 两轮仍失败/修复越权/无变化 | 停止、显式警告，不按块重开预算 |
| 人工改稿 | 旧当前版本评审失效，重核受影响内容与全文 |
| 配音长于画面 | 减稿或补同情节区间，不截尾、定格、慢放 |
| 全文和部分音频已完成 | 不等于整片完成，恢复与交付可区分 |
| 目标时长/画幅 | 原片约30%预算 + 16:9，偏离只警告，不强凑秒或偷改速 |
| 最终文件未完整看片/听审 | 待人工验收，不以技术通过代签 |

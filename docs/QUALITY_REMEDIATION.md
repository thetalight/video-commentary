# 成片质量整改进度（2026-09-14）

本轮针对现有成片审查发现的“短画面承载长配音、重复叙述、字幕长句、原声叠加”做第一阶段整改。不是完整商业质量验收。

## 已实现

- 整片 EditSegment 新增兼容字段 `shots: [[start, end], ...]`。一段叙述连续配音，多段证据画面原速顺序播放；旧稿空数组仍为单区间。
- 所选画面不足时先在 AI 授权的本段时间范围内延展相邻镜头，保留原选镜头与时间顺序；范围仍不足才指出段落。不用定格、慢放、截断语音或跨越本段范围。
- 多镜头范围校验、审稿界面的镜头时间编辑；多镜头段与原声接力段分开。
- 原声段先播放引导解说，然后在原字幕的完整对白起点开放原片声音，需留至少四秒；普通段可按设置静音，或把原片环境声压在人声下。
- Edge TTS 音频与词边界由同一次请求生成，整片解说字幕使用真实词边界；拿不到边界会失败，不再用字符比例冒充精确对齐。
- 更新导演事实检查提示与跨段去重提示，不机械修改人物称呼；多镜头引用仅在选中时间区间核验。
- 导演检查点与视频缓存版本更新，避免重新生成仍复用旧逻辑的稿件和视频。新增片段先写临时路径，成功后进入缓存。

## 本轮继续完成

- 字幕AI纠错派生层、置信度和人物事件图已接入本机 Ollama并保存在导演检查点。不可追溯或置信度无效的派生项会被忽略并记录警告，原字幕继续作为唯一事实来源，不再阻断整章。
- 全片语义去重及带证据的局部修复已接入本机 Ollama，按10段分批且只检查一轮，保存候选与报告。章节已经负责事实核验；整片层只处理人物合同冲突、剧情顺序、称呼、实质重复和说话人元数据，不再多轮压缩文风。只有段号、证据、镜头边界和结构全部合法的单项修改才会进入候选；空修改、歧义项、越界项、无效证据或某批模型失败只记录到 `full-review/warnings.json` 并保留原段。若整轮修改会把旁白压到发布下限以下，整轮修改直接拒绝。
- 分章事实核验改为程序按每段所选镜头生成证据编号，模型只能选择同段编号，不再自由抄写字幕引用；相邻时间段的台词无法串入前一段。缺失、重复或证据编号无效的裁决视为无效审稿意见，不再删除原段；有效的无依据裁决仍会保守修正或删除。事实核验服务或格式失败会保存警告并保留已通过确定性校验的章节候选。
- 粗剪后的本地评审已接入：FFmpeg 检测近似静止、黑场和静音；超过5秒的静止或静音、持续黑场仍会阻止发布。本机 Ollama 对全片均匀抽取最多36帧、分三批做解说匹配、构图和字幕可读性抽查。粗剪文件会先独立验证可读取、非空且有有效时长；视觉模型不可用、返回格式异常或给出主观修改建议时保存报告并发布可播放成片，不再把评审器故障误报成渲染失败。单帧抽查不能替代完整观看。
- Edge TTS 音频与词边界改为同一次请求生成，整片和样片按真实词边界拆字幕；拿不到词边界会失败，不冒充精确对齐。原声接力从原字幕中寻找配音结束后的首个完整对白起点，找不到则要求调整区间。
- AI 多镜头选片已经进入导演结构，并按实测配音原速使用；普通段的本机环境声可在人声下动态压低。设置中可选本机音乐文件，循环铺底并由人声动态压低，默认关闭。
- 模型返回的多镜头在章节入库前会确定性归一化：裁剪到本段授权窗口、按时间排序、合并交叠区间并丢弃不足0.8秒的无效镜头；原声接力段强制使用连续区间。模型的镜头数组表示错误不再导致整章以“多镜头时间无效”失败。
- 整片终审完成后会再次执行时间轴排布，自动利用删段后释放的安全画面空档。仍被相邻剧情或排除区间夹住、画面短于口播的段落交给本机 Ollama 按本段字幕证据和程序计算的最大字数压缩；模型结果逐段校验，缺失或越界时使用只删除原文、不增加事实的保守缩写。最终稿在写入前再次执行画面覆盖检查，不再把必然无法渲染的红色段落交给审稿台。
- 原声接力段在导演稿发布前逐段验证“预计引导结束后仍存在至少4秒完整字幕对白”。程序先尝试在不越过下一段、排除区间或片尾的前提下向后扩选；没有合法对白时自动改为纯解说。渲染取得真实 TTS 时长后再次验证，若实测声音更长导致接力失效，也自动使用纯解说剪辑，不再中止整片。
- 新增统一的确定性时间轴编译器，AI 新稿、任务恢复、人工审稿保存和渲染预检使用同一套规则。原声片段若从对白起点开始，会向前移动画面并为引导保留1.2倍预计余量；普通段会先扩选，仍被相邻段夹住时自动删减到可承载字数。少于三秒、连最短口播都无法承载的碎片直接移除，不再拖垮整片。
- 独立编码的段落不再直接流复制 AAC 音轨；最终拼接会重建连续音频时间戳，避免命令成功但中间出现十几秒静音。剪辑缓存版本已升级，旧片段不会复用。技术检查只把与解说字幕重叠的长静音视为确定性失败，原片自身的安静区间保留为警告。
- 2026-09-20 对真实失败粗剪的逐段检查确认：相邻缓存片段曾分别携带 44.1kHz 与 96kHz AAC，concat demuxer 不会可靠拒绝这种输入，而会在格式边界产出长静音。渲染现在执行明确媒体合同：每段音轨在滤镜输入、混音输出和编码输出三处统一为 48kHz 双声道；缓存命中和最终拼接前都用 ffprobe 验收，旧规格缓存自动删除重建。渲染版本指纹同步升级，因此旧成片不会被误判为当前版本。
- 2026-09-22 修正原声区黑场误判：真实粗剪的 106.2–110.5 秒黑场位于保留原声片段尾部，前一条解说字幕约 78 秒结束，下一条约 118 秒开始；同区间原片静音，属于可能的电影停顿或转场。黑场现在与静音采用相同归因规则：覆盖解说至少1秒才阻止发布；只出现在无解说的原声区则写入质量警告并继续本地视觉评审。技术警告同步进入发布决策，不再悄悄丢失。

## 本地AI边界

- 设置、样片、字幕理解、人物事件图、导演、事实核验、整片语义修复和粗剪视觉评审全部固定使用回环地址上的 Ollama。
- 后端拒绝非 Ollama AI 请求；设置结构已删除云模型字段，读取旧设置时会清除旧供应商和密钥字段。
- Edge TTS、视频下载仍是可能联网的非LLM服务；背景音乐默认关闭。

## 使用与验收

重启新版应用，重新生成 AI 导演稿可使用新多镜头结构。旧稿在重试成片时也会在其现有段落范围内自动补足相邻画面，但不会跨段猜选剧情。
先做小样并确认：事实无新增、镜头没有技术性定格、没有双人声争抢、字幕可读，再扩展整片。
原字幕、META.json及现有任务成片未在本轮整改中改写。

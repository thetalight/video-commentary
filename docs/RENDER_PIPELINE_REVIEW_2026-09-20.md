# 成片工作流深度检查：静音洞与音频主时间轴

日期：2026-09-20

## 结论

本次 `140.7–156.7` 秒长静音不是导演稿缺字、字幕错位或 Edge TTS 无声，而是旧渲染架构允许不同音频规格的段落 MP4 直接进入 concat。相邻片段实测分别为 44.1kHz 双声道和 96kHz 双声道；对应 TTS 源文件均有有效时长、RMS 和峰值，因此声音是在段落封装后的拼接阶段丢失。

旧流程的主要缺陷不是“缺少一次重试”，而是缺少可执行的媒体合同：缓存只要存在就能复用，拼接前也不验证音轨参数。FFmpeg concat demuxer 对不一致的 AAC 流可能返回成功，但在格式边界错误解释时间基并产生长静音。最终成片再编码音频已经太晚，因为错误发生在读取拼接输入时。

## 真实故障证据

- 技术报告记录解说字幕覆盖的 `140.72093–156.747188` 秒为长静音，所以不是刻意保留的无解说空白。
- `rough-cut.pending.srt` 在该区间持续有解说字幕。
- 对应两段 TTS MP3 均可解码且有明显响度，不是空文件或损坏文件。
- 相邻缓存 MP4 的音轨分别为 44.1kHz / 2 声道和 96kHz / 2 声道。
- 旧 concat 命令成功退出，却产出静音洞；这也是之前只重建最终 AAC 时间戳后仍会复发的原因。

## 已实施的整改

1. 建立统一渲染媒体合同：所有段落输出为 30fps、yuv420p、AAC 48kHz 双声道。
2. 普通解说、保留原声、环境声压低、背景音乐四条音频路径都在滤镜输入和最终编码处显式重采样并统一声道。
3. 新片段先写 `.pending.mp4`，通过 ffprobe 合同检查后才进入缓存。
4. 复用缓存前重新检查音频合同；旧的 44.1kHz / 96kHz 片段自动删除重建。
5. 最终 concat 前逐段硬校验；任一输入不合格就提前报出准确段号，绝不生成“命令成功但中间无声”的粗剪。
6. concat 输出仍重新生成连续音频时间戳并编码为 48kHz 双声道，处理 AAC priming 和包时间戳不连续。
7. 同时升级剪辑缓存键和成片设置指纹，旧缓存、旧成片不会被误判为当前版本。
8. 粗剪静音检查继续作为发布闸门，但只阻止与解说字幕重叠的静音；无口播区间的安静原声不误判。

## 与开源项目的对照

- NarratoAI 的 `audio_merger.py` 先创建一条完整静音画布，再按累计位置 overlay 各段 TTS，最终只交付一条音频时间轴。这个方向比“每段 MP4 自带音频后盲拼”更稳定。
- NarratoAI 的剪辑服务显式固定输出音频采样率和声道，说明跨片段格式归一化是拼接前置条件，而不是最终导出选项。
- VideoLingo 把最短字幕时长、可向后延展容差、音频速度范围和原始音频采样率做成集中配置，避免文案、字幕和音频各自决定时长。
- MoneyPrinterTurbo 先生成并测量完整 voiceover，再以音频时长决定视频素材覆盖，最后一次性合成视频、配音和字幕；它把旁白音频视为主时钟。

## 推荐的目标架构

当前整改已经封死本次“混合采样率导致长静音”的路径。长期应进一步改成音频主时间轴架构：

1. 导演稿只生成叙事段、证据镜头和原声接力意图。
2. TTS 后先构建 `audio-timeline.json`，记录每段真实词边界、起止时间、原声窗口、响度和媒体指纹。
3. 所有 TTS、原声和环境声先解码到统一的 48kHz 双声道工作格式，在一条连续时间轴上完成 duck、J/L-cut 和响度处理。
4. 画面按音频主时间轴生成无声视频序列；不足时回到选片层扩选，不定格、不慢放、不截音。
5. 只在发布前把完整视频轨和完整音频轨 mux 一次，再烧录解说字幕。
6. 技术验收按时间轴逐段比对“字幕应发声区间”和真实音频能量；检测器发现问题时可直接定位到音频事件和导演段，而不是只报告成片秒数。

## 仍需单独处理的问题

- 当前任务导演稿残留大量“说话人87 / 说话人306”一类 ASR 元数据。这不造成静音，但明显不适合最终解说。应在 AI 导演发布前执行残留检测，并让本地模型依据上下文重写相关段；程序不应猜人物名，也不应在渲染阶段机械替换。
- 代码测试和媒体合同只能证明管线约束成立，不能代替完整观看。新版首次重渲染后仍需检查开头、原声接力、密集对白、结尾四类场景。
- 真正跨导演段的 J/L-cut 仍未实现；当前只支持段内原声交接和环境声动态压低。

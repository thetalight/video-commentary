# 深度电影解说改造（2026-09-21）

## 目标

用户希望参考成熟长篇电影解说的叙事质量。系统只提炼高层方法：克制叙述、人物中心、主题回扣、尊重原片留白；不复制木鱼水心或其他具体创作者的独特措辞、句式和口头禅，最终形成应用自己的“深度剧情解说”声音。

## 旧稿问题

对现有导演稿和提示链路检查后，质量问题并非单一模型能力不足，而是旧结构主动把模型推向低质量结果：

1. 蓝图只要求“欲望、阻力、危险、钩子”，没有中心问题、人物弧线、关系变化和结尾回应。
2. 分章提示要求每两三段执行一次“埋钩子→证据→兑现”，让生活剧情也被写成密集反转。
3. 要求每句同时说明动机、动作、阻力和后果，模型容易替人物编心理，也会形成说明书句式。
4. 章节按字幕节拍分批后各自追求强开头，整片缺少统一叙述人格，章节之间像多篇短视频拼接。
5. 整片复核重事实和重复，但没有明确检查“逐句转述字幕、某人表示/询问/回应、空泛拔高、人物编号”。
6. 当前真实稿件残留大量“说话人87、说话人306”，证明软性人物称呼提示不足以保证观众可听性。

## 新导演链路

### 1. 字幕节拍

仍只依据字幕提取事件，区分主线、框架节目、片中媒体、回忆和不确定内容。该层只回答“发生了什么”，不提前写文案或调用电影常识。

### 2. 深度叙事蓝图

蓝图从七个方面约束整片：

- 主角当前想要什么；
- 什么现实阻力迫使他选择；
- 失败的具体代价；
- 全片持续追问的中心问题；
- 至少由三处剧情节拍共同支撑的克制理解；
- 人物弧线和关系弧线；
- 结尾如何用人物行动回应开头问题。

蓝图还记录可回扣的重复物件、台词或处境。字幕证据不足时字段应留空或保守描述，不允许用片名常识补全。

### 3. 分章写作

每章先判断自己在人物弧线里的作用，再选择真正改变目标、关系或认识的事件。取消机械的“每两三段造钩子”，改为完整意群：处境 → 选择 → 后果，必要时增加一句有证据的理解。

普通段落建议 24–72 字，不为快切拆碎意思。情绪已经由演员、对白和反应成立时，旁白应少说一句，把空间让给原声。

### 4. 整片编辑

整片本地模型复核新增以下检查项：

- 同义重复和章节重启；
- 逐句转述字幕；
- 连续使用“某人表示、指出、询问、回应”；
- ASR 说话人编号；
- 无依据心理和人物关系；
- 空泛主题拔高；
- 声画时间不足。

修订仍受本段字幕证据和原时间范围约束，不允许为了文风跨段借事实。

### 5. 人物称呼专项修订

整片复核后，程序检测观众文案中的 ASR 元数据。发现“说话人87、speaker_12”等内容时，由本地 Ollama 结合整片蓝图和本段证据重新组织称呼：证据明确才使用姓名或身份；不能确认时省略主语或使用不虚构关系的自然称呼。

应用代码不机械替换、不猜人物名。修订必须提交有效的本段证据，并且结果不能继续残留编号；否则不发布导演稿。

## 缓存和使用

导演提示版本已升级为 `director-v11-script-budget-linear-timeline`。v9 起持久化 `story-model.json` 与 `story-plan.json` 两个独立合同；v10 增加动态 Unit 区间；v11 进一步把 Writer 与 Timeline Mapper 分离：Writer 只按 Unit 交付旁白，程序按 `beat_ids` 绑定镜头，并在写作前把整片发布要求分配为 Unit 级结构化预算。交错的 Story Unit 会被拆成时间单向的连续 run，整片终审也缩减为一次硬问题检查，不能再反复把稿件压短。旧版本检查点不会复用。已有字幕会直接从 AI 导演开始，不重新下载或识别；已有 TTS 和成片只有在新导演稿发布后才按新稿版本重建。完整实现见 [Story Pipeline v11](./STORY_PIPELINE_V9.md)。

## 验收边界

- 程序能够确定性阻止元话语开场和说话人编号，但“是否有余味”仍需要真人观看判断。
- 导演阶段仍只使用字幕，因此不能评价构图、镜头运动、色彩或表演细节；这些只能在粗剪视觉评审中作为建议，不能反向编造剧情。
- 主题判断受字幕证据约束，不承诺复现任何具体影评人的个人知识、阅片经验或表达风格。

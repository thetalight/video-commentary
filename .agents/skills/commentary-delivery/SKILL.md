# 一篇完整稿，一条整集成片

先读 [总控与隐私边界](../commentary-episode/SKILL.md) 和 [现状与目标契约](../commentary-episode/references/contracts.md)。当前主入口为 render_episode，使用 services/episode.rs 与 ffmpeg::compose_landscape；旧短片接口仍保留。

## 出片前

1. 用户已确认原片约30%预算、16:9横屏，不沿用短片顶部标题与模糊背景。当前输出1920×1080等比缩放补边，底部硬字幕裁切比例可调。
2. 全文、方案、字幕与原片版本一致；逐段事实检查、全文连贯性检查、程序校验状态清楚，人工已通读并处理警告。
3. 只有一个合并后的完整稿与有效全文 revision；续写块、事实检查批次不成为独立视频。
4. 所有段落有合法证据和足够原速画面储备，画面不复用；配音使用本机中文 say 音色，音乐仅显式选择的本机文件。
5. 通过 render_episode 操作，必须当前版本程序与双层评审通过、confirmed_review 为真；不直接运行 ffmpeg/say 制作产物。

## 目标媒体流程

`已确认全文 → 完整逐段本机配音 → 实测音频 → 原速分配画面 → 连续剪辑混音 → 最终画幅/字幕合成 → 技术检查 → 人工整片验收`。

- 段落是自然口语意群，不是字幕 cue 或独立章节。分段配音可以缓存，但听感上不能每段都重新开场、机械停顿或音量突变。
- 使用实测音频时长与累计时钟，不能按估计字数固定成片秒数；不沿用 45–75 秒短片警告。
- 画面少于实测配音则缩短有冗余的段落或补同情节镜头，重新审稿；不裁配音尾巴、不定格、不慢放、不拿无关画面填时间。
- 不为装进窗口静默改稿。镜头过碎则减少无必要选片或重排段落，不降低程序门槛。
- 逐段字幕可按音频实测时长估算，必须说明不是逐字强制对齐。长稿应特别检查累计偏移、跨段重叠和重复字幕。
- 音频缓存位于 episode/tts，失败保留诊断目录不写成功输出；部分视频尚无自动续跑恢复。段落完成不等于整片成功。

## 故障与恢复

| 现象 | 最小路径 |
| --- | --- |
| 源材料、全文或方案版本变化 | 失效下游评审/检查点并重核，不手改哈希 |
| 配音长于所选画面 | 改问题段或补同情节画面，重核事实和衔接 |
| 镜头过碎 | 减少碎片，不改速、不定格 |
| 接续段落重复开场/称呼变化 | 回到全文稿，不靠音频剪切掩盖文字问题 |
| 某段静音或配音失败 | 保持未完成，检查本机依赖/音色/音频链，不跳过该段当成功 |
| 最终时长偏差或字幕累计漂移 | 对照每段实测时钟与累计偏移，修合成逻辑，不篡改检查结果 |
| BGM 盖住人声、遮挡或关键画面被截 | 检查当前最终文件，应用重渲染后再验收 |

## 检查边界

旧 `technical-review.json` 来自 BGM/竖屏包装前的 montage，不能证明最终成片字幕、混音、接点或剧情正确。旧每窗从起点比例截取也不能保证关键表演保留。新整集实际在加BGM/烧字幕后的最终文件检查静音、黑场、静止及与配音时钟偏差；这仍不等于视觉匹配、字幕排版、混音听感或剧情全部正确，须人工验收。

技术检查与人工检查分开，不能把中间媒体、缓存或失败目录中的 MP4 当作最新交付。

## 人工验收

请用户在本机对本轮实际最终文件：

- [ ] 正常速度完整看一遍，主要剧情和因果清楚，不是短篇拼接。
- [ ] 完整只听声音，称呼一致、口语自然、没有重复开场、漏读、截尾、异常停顿或音量跳变。
- [ ] 复看所有技术/内容问题点及续写接点，必要时看接点前后约 0.5–1 秒，确认不是虚假因果或半句原声。
- [ ] 检查远距离铺垫与回收，开头承诺与本集结尾一致。
- [ ] 检查整片字幕、画幅与画面遮挡、BGM/原声避让，尤其长时间累计偏移。
- [ ] 逐条处理警告，局部返修未破坏冻结项。

未实际完成就标待人工验收，不代勾。最终报告任务/全文版本、真实输出路径、实测时长、警告与人工验收状态；不上传、不自动发布，不复制真实文案或画面到外部会话。

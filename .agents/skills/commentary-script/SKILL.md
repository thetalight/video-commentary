# 全文统一创作，必要时分段生成

先读 [总控与隐私边界](../commentary-episode/SKILL.md) 和 [现状与目标契约](../commentary-episode/references/contracts.md)。当前整集控制器为 `services/episode.rs`，纯写作指令为 `prompts/episode/write.md`，不要用旧 `shorts::write` 代替。

## 输入必须先统一

使用同一版本的全集故事索引、统一叙事方案、人物称呼表、揭示次序、可回查字幕证据及任务所选风格的一节。摘要与方案只能导航，不能替代字幕事实；不得凭外部知识补人名、动作、动机和结果。

全文目标为原片约30%时长、16:9横屏，约4字符/秒作初始估计，不固定一分钟预算。初稿文本预算以语速估计，最终必须以完整本机配音实测时长为准；字数多不等于剧情完整。

## 优先一次写全文

- 当前应用以100000输入字符作保守预算、长文输出上限24000 tokens；目标稿≤5000字符且输入可容纳时一次写，否则按同一方案连续续写并携带完整前文。它不是精确token估算或无限长支持，超预算会停止。模型标称上下文不等于本应用实际预算。
- 有效预算足够时一次生成整篇候选，统一铺垫、推进、转折和结尾，不先按章节各写一稿再拼接。
- 不能为了“一次写完”静默截去后半集字幕、丢证据或压缩到无法理解。事实依据不足或输出截断的候选不得作为完整稿通过。
- 一次生成仍可能重复、矛盾，不能跳过全文评审。

## 仅超预算时连续续写

每次续写都携带以下状态，绑定源材料版本、方案版本与前文稿件版本：

| 状态 | 用途 |
| --- | --- |
| 全集统一方案与当前叙事节点 | 延续同一条主线，而非重新策划 |
| 稳定人物称呼、关系随剧情的变化 | 防止换名、错认人物或关系回退 |
| 已写节点/事实的简洁记录、必要前文原句 | 防重复；重要承接不只依赖有损摘要 |
| 上一段结尾及本段进入点 | 直接接住前文语义与听感 |
| 已揭示与暂未揭示的信息 | 防止提前公布身份、反转、结局 |
| 已埋未收的铺垫及计划兑现点 | 保留长线呼应 |
| 当前需要的原字幕证据与稳定源 ID | 核事实，不把摘要当证据 |
| 已用画面 ID、预算与下一接续点 | 防重复使用、无关补时与生成失控 |

- 分段只是调用/存储边界，不显示章节标题，不重复人物介绍、问候、开场钩子，不在每块末尾写总结或“下集再说”。
- 只有整篇开头建立总承诺，只有整篇结尾完成总体收束；中段靠实际剧情因果推进，不靠“接下来让我们”硬连接。
- 上述状态由当前已保存正文和方案校验后更新，不能只信模型自称“已经覆盖”。前文修订后重建受影响的状态，不从过期检查点继续。
- 完成后合并为单一全文 revision，再评审全文。若状态不足以稳定接续，停止并扩大必要上下文，不用独立章节降级冒充连续稿。

## 连续口播写作

- 按人物处境、触发、选择、后果和关系变化推进，不逐行复述台词。可压缩支线，但不能删掉后面行动所需的前提。
- 一段是一个自然口语意群，不是独立故事；每段不强求钩子与结尾。适当承接前文指代，不能为“段段独立”反复交代背景。
- 人物称呼清楚一致，关系和知情状态随着剧情推进；区分事实、转述、假设、回忆、戏中戏及本集尚无答案的问题。
- 不编造表情、眼神、外貌或画面动作；字幕时间窗不是视觉观察。
- 禁止套话、空泛拔高、重复事实、营销式连续反问或无证据因果；风格只改变口吻，不改事实标准。
- 不为字幕分行切碎朗读句；字幕拆分由后续应用负责。配音文本不混入编号、Markdown 或舞台提示。

## 逐段证据与画面

- 整集容器为 Episode，每段使用 narration/evidence_quote/shot_ids；字幕窗采用稳定全片 ID，不把 ShortTopic 当全集方案。
- 直接对照原语言字幕写简体中文narration；不先全文译中。引文逐字来自所选字幕的连续原文，至少4个有效字符；英文字幕就引用英文，不以中文译句替换证据。匹配一条引文不代表整段所有事实成立。
- 全稿引用稳定源 ID，程序检查存在性、段内顺序、跨段不复用及时间不重叠；跨块证据不能因重新编号而错位。
- 每段所选画面累计秒数 ≥ narration 字符数 ×0.3，包含标点；空档及整个原片跨度不能算储备。
- 画面不足就减少无必要文字或补选有依据的同情节区间，不拿无关片段凑秒、不靠定格慢放补时。

## 自检与返修

合稿后从头只听文字：是否知道谁在做什么、为什么变化，是否出现重复开场、接点突变、称呼漂移、提前剧透、铺垫消失或结尾失约？交给 [双层评审](../commentary-review/SKILL.md)，不以“写完”冒充“通过”。

局部返修冻结未点名内容；接点问题可同时修相关前后段，但必须明确允许范围。主线有误时回到方案，不让最后一次“全文润色”自由重写所有已核实的段落。

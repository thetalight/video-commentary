# 全集材料索引与统一叙事方案

先读 [总控与隐私边界](../commentary-episode/SKILL.md) 和 [现状与目标契约](../commentary-episode/references/contracts.md)。以下真实文本由应用配置的 DeepSeek API 或人工处理，媒体不作为 AI 输入；当前实现位于 `services/episode.rs`，指令在 `prompts/episode/index.md / story.md`。

## 材料分块，不分割故事

排除规则无标记时保留开头结尾，不固定切60/90秒；模糊音乐/完结/重复对白只记候选。明确署名/广告仅本条区间按设置应用，不吞掉前后剧情。生成记录exclusion-report.json，界面可看候选/已应用及保留位置；更改排除导致材料变化时旧稿失效，不能仅续用旧覆盖报告。

1. 直接读取保留来源语言的规范字幕（不预先逐条译中），事件/人物/方案输出简体中文，证据ID始终指向原文。按模型实际 token 预算读取完整规范字幕，记录每块源 ID 范围、时间范围与处理状态；不截掉结尾或静默跳过失败块。
2. 每块最多48窗、约6000字符，提取有证据的事件、人物提及、关系变化、原因/后果、未决问题及其源ID。程序先保存原始结果，定位缺失ID，每批≤16窗、最多两轮只补遗漏；失败保留诊断并明确数量/ID。完整有效索引绑定源版本/输入/模型/提示指纹缓存复用，不把失败块当完成。非剧情内容按规则排除，不为每块强造完整因果或反转。
3. 跨块事件可先保持未完成，合并时核对边界上下文；重叠读取同一事件须合并证据，不能误判为发生两次。
4. 汇总不是新事实来源。写作可用索引定位，但具体身份、数字、因果与结果仍回查原字幕。
5. 缺材料或有歧义则保留未知，不凭片名补人名，不把“他说”变成“事实如此”。

## 全集索引需要保留什么

- 稳定的源字幕/时间窗 ID 和证据指向，不按写作分块重新编号。
- 人物称呼、已知别名及其依据；无法确认同一人时不要仅凭相近称呼合并。关系可随剧情改变，需保留变化时间。
- 原片事件发生顺序与字幕呈现顺序；回忆、假设、转述、戏中戏单独标明。
- 主线目标、冲突、关键选择、代价、结果；支线是否是理解后续的必要前提。
- 明确因果和仅有先后关系的区别；不确定推论不能升格为事实。
- 铺垫、揭示、人物知情状态与本集结尾未解决的问题。

当前程序用 IndexBlock/Event/Story/Beat/Coverage 记录索引与方案，每个事件需 keep/omit 理由，保留事件需节点引用。程序能检查范围与引用覆盖，但不能机械证明剧情语义完整；不要手写真实任务记录冒充生产结果。

## 形成一份全文方案

从全集索引统一决定：

1. 观众看完这一集解说应理解什么，贯穿整篇的核心问题是什么？
2. 主要跟随谁的经历？多线剧情何时切换才不丢人和因果？不为“单主角”硬删理解结局所需的支线。
3. 哪些前提必须保留，哪些重复/无关内容可以压缩？覆盖的是主要剧情，不要求每句台词都进入稿件。
4. 开头如何引入整集问题？哪些答案必须延后才能保住揭示顺序？
5. 各叙事节点承担什么新信息或变化，前后如何接续？节点是内部规划，不是独立章节或短片。
6. 结尾落在本集已呈现的结果或真实悬念，不编造后续集结局。

默认按因果清楚的剧情推进；有意倒叙时记录叙述顺序与原片时间的区别，避免提前泄露关键反转。使用内部节点做覆盖和预算检查，不让每个节点单独起承转合。

## 交接与检查

向写稿交付同一版本的全集方案、人物称呼表、证据索引、揭示次序与内容边界。时长已确认按原片约30%做初始预算，不套用230–300字、2–8条或300秒窗口等短片参数。

检查遗漏的关键前提、跨块重复事件、混淆人物、无证据因果、提前揭示和未回收铺垫。若材料超过当前安全输入预算，实现会停止并保留记录，不只读开头就称“理解全集”；多级索引和自动恢复仍待扩展。

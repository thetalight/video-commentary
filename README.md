# 视频解说

基于 **Tauri 2 + React + Rust** 的桌面应用：粘贴视频链接，自动下载并获取字幕，由配置的 DeepSeek API 梳理整集字幕，制定统一方案并写一篇连续全文，经事实与连贯性评审、人工审稿后生成 **16:9 横屏长视频解说**；原片约30%时长作为初始预算，不强制凑秒。AI 梳理、写稿与评审会将原语言字幕、文案文本发送到配置的 API；原片画面和音轨不作为 AI 输入，转写和配音仍在本机。下载走 **yt-dlp**，凡它能解析的站点都可以。

主界面已接入整集链路，旧 `shorts/` 数据保留不覆盖。实现与限制见 [docs/COMMENTARY_SKILLS_DESIGN.md](docs/COMMENTARY_SKILLS_DESIGN.md)：目前超安全输入预算明确停止，正文检查点仅供诊断，尚无完整自动续跑；已通过覆盖校验的字幕索引块会缓存复用，遗漏ID会在有限轮次内单独补充。

整体架构与数据流见 [docs/ARCHITECTURE_AND_WORKFLOW.md](docs/ARCHITECTURE_AND_WORKFLOW.md)。

## 流程

1. 粘贴链接，下载视频。
2. 获取字幕：平台独立字幕 → 视频内封文字字幕 → 本机 whisper 转写（可关闭）；保留原语言字幕和时间戳，DeepSeek 直接理解原文、输出中文解说，不先全文译中。都没有，或质量检测不通过，就放弃这个视频。
如果旧任务显示“翻译失败：…已保留原文”，重新启动应用后点“重试字幕准备”。应用会优先检查并复用已保存的合格原字幕，不重下、不重转写、不再翻译；字幕缺失、来源不支持或质量不合格时仍按正常流程重新获取。不需要删除任务，也不要手改字幕或状态。旧翻译缓存会保留但不再使用；已成功安装的旧译文不会被自动回滚，若要换回原文需通过应用重新获取字幕并重新生成稿件。

3. 点“生成整集解说全文”：读取全部有效字幕窗、梳理事件与人物、制定一份方案；优先一次写完整稿，超出单次生成预算才按同一方案连续续写，不独立分章节。
4. 查看逐段事实与全文连贯性评审结果；可点“AI审查并自动修稿”处理已有稿，最多两轮修改并重新评审。证据不足会尝试查上下文、纠正或删减推断；未通过仍显示原因、不允许出片。
5. 人工编辑标题、文案、引文、选片后点“保存草稿”，修改会使旧评审失效；重新评审通过后通读整篇并勾选人工确认。
6. 点“生成整集横屏视频”：macOS本机配音 → 实测时长/原速剪辑 → 可选本地BGM → 16:9字幕合成 → 最终技术检查。完整看片和只听声音验收仍由人完成。

成片为1920×1080横屏，原画面等比缩放补边，解说字幕白字居底，不使用竖屏模糊背景或全程顶部标题。字幕按本机配音实测时长估算，可能有字词偏差。原片底部默认裁掉18%隐藏硬字幕，可在设置选择不裁或调整比例；原片声音压低并自动避让，亦可静音。

出片前会自动检查：解说在播却没有声音会直接报错，不发布；画面接近全黑或长时间静止只给出时间点提示，由你决定是否换镜头。

## 任务目录

开发运行时任务位于仓库的 `inbox/`；独立安装且没有源码目录时位于当前用户的应用数据目录 `com.esun.video-commentary/inbox/`。设置页显示实际路径。

```
inbox/
  tasks.sqlite                 # 任务状态
  {task_id}/
    META.json                  # 标题、链接、时长、风格
    job.json                   # 任务状态快照（诊断用）
    source.mp4
    TRANSCRIPT.srt             # 保留来源语言的规范字幕，时间戳不变
    TRANSCRIPT.source.json     # 字幕来源
    episode/
      episode.json             # 当前统一方案、全文、证据、版本、评审与输出
      runs/                    # 全集索引、方案、生成检查点、逐轮评审与局部修复
      tts/                     # 本机配音缓存（按文案与音色哈希）
      renders/run-*/episode.mp4 # 一条16:9横屏成片；同目录有字幕和最终技术报告
    shorts/                    # 旧短片数据保留，新链路不覆盖
```

## 环境要求

```bash
# macOS
brew install yt-dlp ffmpeg-full   # 字幕烧录需要 libass，应用会自动找到可用的 ffmpeg
```

配音使用 macOS 已安装的中文音色，可在设置里试听；配音本身不调用语音云服务，但 AI 写稿与评审会发送文本到配置的 API。背景音乐只读取本机文件，留空不添加。

## DeepSeek 后端配置

仓库根目录已提供 `.env.example`；开发时复制为 `.env` 并填写：

```dotenv
DEEPSEEK_API_KEY=你的API密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

- 模型名大小写按配置原样发送，不自动映射或回退。官方接口已实测支持 `deepseek-flash`，不接受此前的 `DeepSeek-V4.1-Flash` 字符串；后者在官方地址会给明确配置错误。若使用中转，以该服务实际列出的ID为准，不据此推断模型版本等价。设置中“检测连接”核对模型列表，不触发文本生成。
- `DEEPSEEK_BASE_URL` 是 HTTPS 基础地址，可带 `/v1`，不要填写 `/chat/completions`；不能含账号、查询参数或片段。只有回环测试地址可用 HTTP，请求不跟随重定向。
- 配置由 Rust 运行时读取，不编译进前端；**不要使用 `VITE_` 前缀存 Key**，不要提交 `.env`。缺 Key 就报错，不回退 Ollama。旧设置中的 Ollama 字段仅为兼容旧数据保留，已不参与 AI 请求。
- 进程环境变量优先于文件（显式空 Key 同样优先并导致报错）。修改文件后下一次请求生效，运行中的请求保持原配置。
- 指定 `DEEPSEEK_ENV_FILE=/绝对路径/.env` 可选择配置文件。开发构建默认读取仓库根 `.env`，没有则尝试应用数据目录；打包应用默认只读当前用户应用数据目录 `com.esun.video-commentary/.env`（macOS 通常为 `~/Library/Application Support/com.esun.video-commentary/.env`），不从启动目录或构建机源码目录加载。配置文件不打进安装包。
- 不自动全文翻译字幕，事件索引/方案/解说稿直接输出中文，证据引文保持原文（例如英文）。省去完整译文的生成，不代表后续写稿评审没有 API 用量。
- 设置页不会显示 Key，错误也隐藏服务响应正文，避免回显密钥或稿件。自定义 API 由你确认可信；只会把模型阶段需要的文字发给该地址，不上传视频、图片、音频。

模型返回完整JSON但结构不合格时，程序会给出不含正文的字段路径诊断并自动格式重试一次；仍失败则停止，不绕过证据/全文校验。HTTP错误、输出截断或空正文不盲重试，格式重试会增加一次API用量。

## 可选：AI修稿联网查证

在同一后端`.env`填写 `TAVILY_API_KEY=你的Tavily密钥` 即启用，留空不联网搜索，仍按字幕自动审查/修改。初次生成和单独重评都支持；每个工作流最多3次basic查询，仅需要时搜索，不会无限循环。

搜索关键词可能包含人名、片名或语法词，发送给Tavily；结果摘要随后给DeepSeek辅助理解。不会把整份字幕或稿件送入搜索，不自动抓页面/执行网页。网络资料不替代本集字幕、不能伪造引文或时间，也不能用小说/其他集补剧情。查询、采用用途和来源会保存在本机运行记录，界面可查看；搜索失败不视为通过。

重启后点“AI审查并自动修稿”，当前稿先复核、再仅修改问题段、再次核事实与连贯性。通过后保存当前版本AI终稿（仍需你通读确认才可出片）；确实无法修复的原始转写或结构问题仍标待人工，不保证任意坏字幕都能生成可靠终稿。
